# Rules and expectations

Checked on 15 October 2026. Read the [official rules](https://www.wemakedevs.org/hackathons/falkordb/rules) before submission. This compact checklist paraphrases the requirements; it does not replace them.

## Compliance checklist

| Requirement | Submission evidence |
| --- | --- |
| One team per participant; maximum four people | Registration |

| Public code | Repository URL |

| Show a working demo | Video |

Participants retain their intellectual property. Plagiarism, judging manipulation, and rule violations can disqualify an entry. AI-generated work without meaningful participant contribution, verification, or understanding can be rejected. [Official rules](https://www.wemakedevs.org/hackathons/falkordb/rules).

The [schedule](https://www.wemakedevs.org/hackathons/falkordb/schedule) gives the build window as 15 October 2026, 12:01 AM IST, through 18 October 2026, 11:59 PM IST. Register and submit before the closing time. Keep a submission buffer; do not use the final hour for first deployment.

## Three tracks

| Track | Core behavior |
| --- | --- |
| Agents That Act on Connected Data | Uses relationships to choose and perform actions |
| Agent Memory and Coordination | Maintains and updates shared or persistent agent state |
| Company Brain | Connects organizational knowledge, ownership, and decisions |

The [overview](https://www.wemakedevs.org/hackathons/falkordb) permits multiple tracks in one project. Company Brain emphasizes documents, tickets, chats, current knowledge, decision lineage, and sourced answers. Our primary entry should be Company Brain. Additional tracks require demonstrated behavior, not extra marketing language.

## Expectations versus invented criteria

The public pages reviewed do not publish numeric judging weights. They do not establish a required video duration, a mandatory agent framework, or a requirement to use every listed integration. Confirm submission-form details when available.

Our recommended internal priorities are graph necessity, correct behavior, a clear user problem, reproducibility, and a short working demonstration. These are our strategy, not an official scoring rubric.

The [resources page](https://www.wemakedevs.org/hackathons/falkordb/resources) links setup guides, clients, Cypher, algorithms, examples, and community support. Use those for implementation checks. No registration, account creation, or submission was performed during this research.

## Data interpretation

Use entirely synthetic people and customer records for this entry. The rules explicitly exclude several kinds of restricted information. Do not assume employee access to a real Slack workspace authorizes loading its contents into a public hackathon graph. Synthetic permission scenarios can test access behavior without importing real private information.
